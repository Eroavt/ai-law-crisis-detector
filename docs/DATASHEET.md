# Datasheet — ALDC Synthetic Suicide-Crisis Conversation Corpus

Following Gebru et al., *Datasheets for Datasets* (CACM 2021).

## Motivation

**For what purpose was the dataset created?**
To support a clinically-grounded, jurisdictionally-aware research artifact that
evaluates whether commercial LLM chatbots correctly detect and respond to user
suicidal ideation. The corpus is *evaluation data* for the ALDC detector and
for an Industry Scorecard against OpenAI, Google, Anthropic, and Character.AI.
It is not training data.

**Who created it?**
Erik Avtandilyan, Athira Ashokan, Nishant Kumar Singh, University of Zurich,
*AI: Technology and Law* (FS26), Profs. Florent Thouvenin and Abraham Bernstein.

**Who funded it?**
No external funding. Compute donated by Erik's personal Claude Max
subscription via `claude -p`; supplementary live-provider testing on small
self-funded OpenAI / Google AI Studio credits.

## Composition

**What do the instances represent?**
Synthetic chat dialogues between a fictional user and a generic AI chatbot.
Each conversation is parameterised by:

- a legal axis (one of 7: `knowledge_seeking_trap`, `anthropomorphic_dependence`,
  `multi_turn_drift`, `method_availability`, `vulnerable_user`,
  `false_positive_baseline`, `privacy_vs_intervention`);
- a target C-SSRS severity level (0–5);
- a demographic profile (age band + context tags such as bereaved / divorced /
  isolated / philosophical_only);
- a conversation length (short ≤ 6 turns or long ≤ 20 turns);
- a language (en / de / fr / it).

**How many instances?**
MVP: 35. Full release: ~300 (English) + 18 (DE/FR/IT subset) = ~318 dialogues.

**What data does each instance consist of?**
A JSONL row conforming to `Conversation` in `src/aldc/schemas.py`:
- `id`: short opaque identifier (e.g. `raine_01`, `kst_03_de`).
- `turns`: list of `{role: "user" | "assistant", content: str}`.
- `ground_truth`: structured labels including C-SSRS level, ASQ-4 booleans,
  legal axis tag, expected action tier, demographic profile.
- `language`: ISO 639-1 code.
- `generation_notes`: model-generated rationale for the dialogue (provenance).
- Optional `exhibit_id` for the paper-appendix anchor.

**Is there a label/target for each instance?**
Yes — the `ground_truth` block. Each conversation is parameterised at
generation time, then the model re-rates the severity it actually produced;
the stored ground truth reflects what the model believed it produced. A
human review pass on the 12 dialogues in `data/exhibit_set.jsonl` validates
the headline cases used in the paper.

**Is any information missing from individual instances?**
No real identifying information was ever present. There are no names,
addresses, phone numbers, or geolocations beyond the synthetic Swiss /
European context.

**Are there recommended data splits?**
The full corpus is for evaluation only. There is no train / dev / test
split because no fine-tuning is performed. The 12 hand-curated exhibits are
the paper's worked-example slice.

**Are there any errors, sources of noise, or redundancies?**
Yes. (a) Sonnet-generated dialogues occasionally deviate by ±1 C-SSRS level
from the requested severity; we log a warning and keep the actual-delivered
severity as the ground truth. (b) Synthetic distributional shift relative to
real chat logs is a known limitation, partially mitigated by the optional
UMD Reddit Suicidality Dataset validation arm.

## Collection process

**How was the data acquired?**
Generated by Claude Sonnet 4.6 (model: `claude-sonnet-4-6`) under the
parametric prompt in `src/aldc/prompts/corpus_generator.txt`, with output
enforced via JSON Schema. Generation backend: `claude -p` routed through the
authors' Claude Max subscription.

**When was the data generated?**
Between 8 May 2026 and 14 May 2026, in the run-up to the submission deadline.

**Were ethical review processes conducted?**
The artifact is a Master's-level course project; UZH does not require IRB
review for synthetic-data research that produces no human-subjects data.
The ethics statement in `docs/ETHICS.md` documents the safeguards the
authors imposed on themselves.

**Does the dataset contain confidential data?**
No.

**Does the dataset contain data that might be offensive, insulting,
threatening, or might otherwise cause anxiety?**
Yes — the entire corpus contains simulated user expressions of suicidal
ideation by design. This is the explicit subject of the artifact.

## Preprocessing / cleaning / labelling

**Was any preprocessing done?**
JSON Schema validation on every generated dialogue. Discards on schema
violation (with retry up to 3× via tenacity). No filtering on content
beyond schema correctness.

**Is the software available?**
Yes — `src/aldc/corpus_gen.py` and `scripts/01_generate_corpus.py`.

## Uses

**Has the dataset been used for any tasks already?**
This artifact's evaluation. Specifically: clinical-instrument classification
(C-SSRS + ASQ), inter-rater agreement (Cohen's κ), three-arm baseline
contrast (naive / policy-only / detector-wrapped), live-provider scorecard,
multi-turn adversarial probing, cross-lingual robustness.

**Is there a repository that links to any/all papers/systems that use it?**
The paper *Duty, Defect, and Disclosure: Reassessing Developer Liability for
LLM Chatbots in Suicidal Crises under the EU and Swiss Law* (UZH FS26).
This repository's `CITATION.cff` will be updated with the DOI on publication.

**What (other) tasks could the dataset be used for?**
- Calibration of new C-SSRS classifiers.
- Stress-testing future LLM safety policies.
- Comparative jurisdictional analyses beyond Swiss / EU.

**Are there tasks for which the dataset should NOT be used?**
- Fine-tuning generative LLMs on these dialogues (would create models that
  generate this content).
- Training keyword filters or content moderators in production (the dataset
  is too small + too patterned).
- Any clinical use whatsoever.
